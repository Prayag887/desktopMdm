# Desktop-only security boundaries

- No hosted backend, socket client, enrollment, remote command handler, or portal is present. Device health stays on this PC. A temporary embedded LAN listener serves QR dismissal only during an explicitly started simulation.
- The installer requires administrator access. Program Files protects the installed binaries; ProgramData permissions give administrators/System write access and ordinary users read access to local health.
- The GUI's health refresh requests UAC approval to run the local companion. Denial is reported; it is not bypassed.
- An administrator retains ordinary recovery and uninstall access. Absolute uninstall prevention and operating-system lockout are not implemented.
- BIOS manufacturer/model detection is read-only. Local BIOS administrator-password set/change is available only through documented OEM interfaces: Dell Command | Configure, HP CMSL, Lenovo WMI (change only), and ASUS ACT on compatible models. Acer and unsupported models use the explicit UEFI-restart fallback; no guessed generic firmware command is executed.
- BIOS fields are masked, never logged or transmitted, cleared on submission/tab exit, and held in zeroizing Rust buffers where practical. For UAC, plaintext is sent over a local child-process stdin to Windows DPAPI; only machine-scoped DPAPI ciphertext is staged in the current user's protected temporary directory, and both the UI and elevated helper delete it after use. Machine scope permits an administrator account entered at UAC to decrypt the handoff. The elevated helper necessarily materializes plaintext briefly in memory, and Dell/ASUS vendor CLIs necessarily receive it as a process argument; an administrator able to inspect process memory or command lines during that short window may observe it. GUI/text-input and allocator copies cannot be guaranteed erased.
- BIOS changes require UAC approval and the existing password when the OEM reports one is set. The workflow never bypasses, recovers, removes, or guesses a forgotten password. OEM firmware policy, password character rules, supported models, and reboot requirements still apply.
- Payment-restriction mode shows a branded screen (not a fake BSOD), never invokes crash APIs, disables OS recovery, or makes itself unkillable, and never saves/relaunches state. Escape is not a dismissal shortcut. Exits: technician (admin) button, offline recovery code, QR dismissal, normal close, reboot, and a five-minute timeout. The health service never starts it. See `docs/payment-restriction-architecture.md`.
- Enforced mode activates only when the app is launched as the enrolled user's Winlogon shell AND the account is not a local administrator. It then auto-enters the restriction screen, hides the Exit button, holds fullscreen, and vetoes Alt+F4 / window-close (`CancelClose`). It never auto-times-out; release is via an owner-signed unlock token, an administrator signing into their own never-restricted account, or WinRE.
- Unlock tokens are Ed25519-signed offline by the owner's private key; the device embeds only the public key and verifies tokens with no backend. Each token is bound to one device id, carries a short expiry and a monotonic counter (persisted in `unlock-counter.txt`) for rollback/replay protection, and is rejected fail-safe (stays locked) on any error. Crypto is in `crates/emi-core/src/recovery.rs`; owner tools are the `keygen` and `mint-unlock` examples. Replace the LAB `OWNER_PUBLIC_KEY_HEX` with your own key before production. Administrators and any normal launch stay in the reversible demo with an Exit button. Admin detection is a read-only Administrators-group (S-1-5-32-544) check; shell detection is a read-only HKCU registry query. WinRE and admin accounts are never restricted.
- The app cannot block OS-global Alt+Tab, Win, or Ctrl+Shift+Esc — no user-mode app can. Those require the Windows Keyboard Filter (WEKF) feature applied by `Set-PaymentRestriction.ps1` on Enterprise/Education/IoT. Within the app, Escape and Alt+F4 are neutralized and key/text events are drained except in the recovery field.
- Keyboard suppression in the prototype is window-scoped only: the app drains its own key/text events on the restriction screen EXCEPT while the recovery field has focus, so the customer can always type a recovery code and accessibility stays usable. It does not and cannot block OS-global Alt+Tab/Win/Ctrl+Shift+Esc; production uses the Windows Keyboard Filter (WEKF) feature for that, never a custom keyboard driver. The keyboard is never fully disabled.
- QR dismissal uses a random per-session UUID token and explicit POST; GET/prefetch is non-mutating. Host/Origin checks, no-store/CSP headers, private-interface binding, 8 KiB header limit, a one-second request deadline, one serial worker and no request-body processing limit exposure. The listener is closed on session teardown. Requests do not access device health or credentials. Plain HTTP means a trusted LAN is required; no public forwarding/tunnel is supported.
- Payment schedules remain domain types, not an implemented storage/editor/payment-processing system. Do not treat local files as payment confirmation from a financial provider.
- Existing database volumes, historical files, and previous releases are retained. Updated initialization removes obsolete server/token fields from configuration while keeping the local UUID. It does not delete other historical state.
- The optional WinGet bootstrap downloads from Microsoft's official endpoint. Use SkipWingetBootstrap for offline installation; the Rust app itself does not require WinGet.
- The release workflow Authenticode-signs the binaries when `CODE_SIGN_PFX_BASE64` / `CODE_SIGN_PFX_PASSWORD` secrets are configured; otherwise it builds unsigned. Signing establishes publisher identity (and cuts SmartScreen "unknown publisher") but does NOT stop behaviour-based AV detection: the app's keyboard hook, Task Manager policy, shell replacement and lockscreen legitimately look like lockware, so on managed devices you must also allow-list the signed app via Defender/MDM. Windows CI compilation/tests do not replace a real GUI/UAC/service/resume smoke test.
